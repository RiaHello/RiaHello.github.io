# Tolis 交互水面动效：技术分析与复刻参考

> 整理日期：2026-10-25\
> 分析对象：Tolis C 受 boat.dev 首屏插画启发制作的交互水面\
> 文档用途：技术调研与后续复刻参考，不代表已拿到原作源码\
> 当前项目：RiaHello.github.io（Vue 3 + Vite）

## 1. 结论摘要

这个效果的核心不是常规 CSS 入场动画，而是三类机制的组合：

1. **可交互的水波位移场**：指针向水面注入扰动，波纹扩散、衰减，并使手绘水纹发生局部弯曲。
2. **具有惯性的漂浮物体**：木桶发生平移、旋转、浮动和倒影变化，呈现一定的浮力、阻尼或弹簧运动特征。
3. **手绘渲染层**：不规则排线、交叉阴影、轻微线条抖动和纸张质感，让实时渲染看起来接近钢笔插画。

若目标是复刻，推荐采用：

- **Vue 3 + Vite**：负责组件挂载、生命周期和页面集成，沿用当前项目。
- **原生 WebGL2 + GLSL**：负责水波纹理、线条/材质扰动、木桶与倒影绘制。
- **JavaScript**：负责交互、简化波动模拟、物体运动与 `requestAnimationFrame` 主循环，与当前项目保持一致。
- **Pointer Events**：统一鼠标、触控和手写笔输入。
- **GSAP（可选）**：当前项目已安装，可用于周围 UI 或参数过渡，不建议把它当作水波位移场和逐帧物理模拟的核心。

**原作是否使用原生 WebGL2、Three.js、某个物理库或具体前端框架，目前没有源码级证据。**上述技术栈是基于录屏表现、公开资料和复刻成本形成的推荐方案，不是对原作依赖的断言。

## 3. 动效拆解

### 3.1 水面手绘纹理

画面中的水不是一张简单左右平移的背景图，而更接近大量不规则水平短线组成的程序化纹理：

- 线段长度、间距和深浅存在随机变化。
- 线条整体保持水平方向，维持“水面”的阅读感。
- 指针附近出现同心波纹和局部线条弯折。
- 线条有轻微时序变化，形成手绘动画常见的 “boil” 效果。

实现时应区分两套坐标：

- **纸张/屏幕坐标**：控制排线密度和手绘风格，避免纹理随水波整体游动。
- **水面坐标**：控制波纹位移、物体浮动和倒影形变。

### 3.2 指针与水波

可见行为更接近“向二维高度场注入冲量”，而不是播放固定路径动画：

1. 指针移动或按下时，在对应位置产生扰动。
2. 扰动向周围传播并逐步衰减。
3. 根据波面高度或梯度计算 UV 偏移，使水纹、倒影和物体视觉受到影响。
4. 指针停止后，水面在阻尼作用下恢复平静。

初版不必实现完整流体动力学。若干衰减径向波的叠加，或二维波动方程高度场，都足以接近录屏表现。

### 3.3 木桶运动

木桶至少包含以下状态：

- 平面位置与速度。
- 朝向、角速度与回正趋势。
- 垂直浮动或视觉缩放。
- 与波面相关的倾斜和倒影变化。

录屏不足以判断木桶是：

- 预绘制的 2D 图片/序列帧；
- 放在 WebGL 平面上的纹理精灵；
- 真正的 3D 网格；
- 或程序化 SDF/光线步进绘制。

复刻时优先使用**带透明通道的木桶图集 + WebGL 四边形**。只有确需自由视角和真实三维光照时，才值得引入 3D 模型。

### 3.4 倒影

倒影不需要独立流体模拟，可由主物体变换派生：

- 将木桶 sprite 垂直翻转并压扁。
- 降低透明度，并混入水面颜色。
- 按波面梯度扭曲倒影 UV。
- 让倒影跟随物体位置，但削弱其旋转和浮动幅度。

### 3.5 动画节奏

推荐把“物理流畅度”和“手绘抖帧”分开：

- 物理与交互：以 60 Hz 或固定时间步更新。
- 手绘线条的重生成：可降至约 8–12 Hz。
- 合成与显示：跟随 `requestAnimationFrame`。

这样既保持指针响应顺滑，又避免所有线条每帧完全随机而产生刺眼噪点。

## 4. 技术选型判断

| 技术 | 对原作的判断 | 对复刻的建议 |
| --- | --- | --- |
| JavaScript / TypeScript | 实时 Web 交互所需，具体语言未知 | 当前项目沿用 JavaScript |
| WebGL2 + GLSL | 中高概率，适合全屏位移、纹理和大量线条 | 推荐 |
| Canvas 2D | 也能做出近似效果，但高分辨率全屏形变成本更高 | 可用于低保真原型或降级方案 |
| Three.js | 无法确认；即使使用，也仍需自定义 Shader 和模拟逻辑 | 团队熟悉时可选，不是必需品 |
| Vue / React | 无法确认，且不决定动效质量 | 沿用当前 Vue 3 |
| GSAP | 无法确认，不适合单独承担逐像素水波模拟 | 仅作外围动画辅助 |
| Matter.js / Planck.js | 无法确认，录屏也不需要完整刚体系统才能成立 | 默认不引入 |
| Rive / Lottie | 任意指针扰动和实时耦合不符合其典型优势 | 不作为主方案 |
| 完整流体引擎 | 没有证据，且实现成本高 | 不需要 |

## 5. 当前项目的推荐架构

```text
Vue 页面
└── 水面容器组件
    ├── 生命周期：mount / unmount / resize / visibility
    ├── 输入层：Pointer Events → 世界坐标与扰动事件
    ├── 模拟层
    │   ├── 波面高度、速度或径向波参数
    │   └── 木桶位置、角度、速度、阻尼
    ├── WebGL 渲染层
    │   ├── 水纹与纸张 Shader
    │   ├── 木桶 sprite / instancing
    │   └── 倒影与最终合成
    └── 降级层：静态封面或减少动态效果
```

关键边界：

- Vue 不保存每帧变化的高度场、粒子或像素数据，避免触发响应式系统开销。
- 模拟与渲染对象放在组件实例内部的普通 JavaScript 对象中。
- 组件卸载时取消 RAF、移除事件监听、断开观察器并释放 WebGL 资源。
- 将模拟、渲染和输入拆成可独立测试的模块，不把全部逻辑堆进 SFC。

## 6. 两种水波实现路线

### 6.1 路线 A：衰减径向波叠加

每次有效指针操作记录一个波源：

```text
center、startTime、amplitude、wavelength、speed、decay
```

某点到波源的距离为 `r`，传播时间为 `t`，可用类似下式计算位移：

```text
wave = amplitude
     × sin(k × r - omega × t)
     × exp(-spatialDecay × r)
     × exp(-timeDecay × t)
     × propagationEnvelope(r, t)
```

优点：

- 实现快、参数直观、无需额外帧缓冲。
- 很适合先验证视觉和交互。

限制：

- 波源数量需要设上限。
- 多次扰动的自然叠加和边界反射不如高度场真实。
- 每个像素遍历过多波源会增加 GPU 成本。

### 6.2 路线 B：WebGL2 高度场 Ping-Pong

用两张浮点纹理保存当前和上一时刻的波面状态，交替读写：

```text
nextHeight = (2 × height - previousHeight
             + c² × laplacian(height)) × damping
```

指针向高度或速度通道注入高斯冲量；渲染时读取高度梯度，计算水纹和倒影的 UV 偏移，同时供木桶采样。

优点：

- 波纹自然传播、叠加和衰减。
- 波源数量增加时，不必在最终 Shader 中遍历全部历史波源。
- 更接近录屏中连续、可反复扰动的水面。

成本：

- 需要浮点渲染目标、帧缓冲和纹理状态管理。
- 要处理浏览器能力检测、纹理精度和上下文丢失。
- 调试难度高于径向波。

建议先用路线 A 验证风格，确有必要再升级路线 B。不要一开始就实现完整流体求解器。

## 7. 每帧更新顺序

```text
1. 读取已排队的指针事件，转换为水面坐标
2. 限制真实帧间隔，避免切回标签页后模拟爆炸
3. 以固定时间步更新波面与木桶运动
4. 从波面高度/梯度更新木桶浮动、倾斜和倒影参数
5. 按较低频率更新手绘线条噪声种子
6. 绘制水面、木桶和倒影
7. 请求下一帧
```

固定时间步可使用 1/60 秒，并限制单帧最大补偿次数。渲染可插值，但不是初版必需项。

## 8. 交互与视觉细节

- 指针移动应按距离或速度阈值注入波源，避免每个原始事件都生成波纹。
- 高频 `pointermove` 先记录最新状态，在 RAF 中统一消费。
- 拖拽时使用 Pointer Capture；按需求设置 `touch-action`。
- 木桶运动使用阻尼弹簧或速度衰减，避免直接跟随指针造成生硬感。
- 排线随机数应可复现；不要每帧无约束地调用随机数重建所有纹理。
- 纸张颗粒应保持稳定或缓慢变化，水波主要影响局部排线，而不是让整张背景闪烁。
- 控制木桶数量、波幅和倒影对比度，优先保留插画的留白和清晰度。

## 9. 性能、兼容性与可访问性

### 性能预算

- 设备像素比建议封顶在 1.5–2，按实际 GPU 测试调整。
- 高度场可使用画布宽高的 1/4–1/2 分辨率，最终合成再放大。
- 限制波源、木桶和手绘线段数量，避免每帧创建临时数组或纹理。
- 页面不可见或组件离开视口时暂停模拟。
- 使用 `ResizeObserver` 处理容器变化，避免只监听窗口尺寸。

### 降级策略

- WebGL2 或浮点渲染目标不可用时显示静态封面，或切换到无位移的 Canvas 2D 简化版。
- 处理 `webglcontextlost` / `webglcontextrestored`，避免丢失上下文后留下空白区域。
- `prefers-reduced-motion: reduce` 下关闭持续漂动和自动扰动，保留静态插画或仅允许明确操作后的轻微反馈。

### 可访问性

- 纯装饰画布应从辅助技术中隐藏，并提供静态替代视觉。
- 如果木桶具有业务操作含义，不能只提供画布内点击；应提供可聚焦的等价 DOM 控件。
- 不将关键文本、链接或导航只绘制在 Canvas 中。

## 10. 推荐复刻顺序与验收点

| 阶段 | 内容 | 验收重点 |
| --- | --- | --- |
| M1：静态风格 | 纸张、排线、木桶与倒影 | 无动画时也接近目标插画；缩放不模糊 |
| M2：指针涟漪 | 径向波、水纹局部位移 | 指针位置准确；停止操作后自然衰减 |
| M3：漂浮物体 | 木桶漂移、旋转、阻尼、倒影联动 | 不抖动、不瞬移；帧率变化不改变运动速度 |
| M4：手绘节奏 | 低频线条 boil、细微颗粒与阴影 | 有手绘感但不闪烁、不干扰阅读 |
| M5：工程收尾 | DPR、暂停、降级、触摸与 reduced-motion | 移动端可用；后台不空转；无 WebGL 时仍有内容 |

建议同时在桌面 Chrome、Safari 和至少一台真实触屏设备上验证。性能验收应记录帧时间和 GPU/CPU 瓶颈，而不只看平均 FPS。

## 12. 最后结论

对当前项目最有价值的结论不是“猜出原作安装了哪个包”，而是把效果正确拆成：

**水波模拟 + 漂浮体运动 + 手绘 Shader + 生命周期/降级管理。**

在没有原作源码的情况下，采用 Vue 3 承载、原生 WebGL2/GLSL 渲染、JavaScript 驱动简化波面与弹簧运动，是成本、效果和依赖规模较平衡的复刻路线。React、Three.js、GSAP 或完整物理引擎都不是这个视觉效果的必要前提。
